# Rewrite plan comparison and consolidation decisions

Prepared 2026-09-07. Compared `rewrite-plan-astra.md`, `rewrite-plan-sol.md`, and `rewrite-plan-terra.md` against the revised `rewrite-direction.md` and the user's explicit instruction that **all current game capabilities, including stock trading, belong in the eventual rewrite**. The companion `rewrite-plan-consolidated.md` is the execution plan to use next. The three source plans remain unchanged as independent planning evidence.

## Recommendation

Use Sol's explicit staged integration and evidence layers, Astra's failure semantics and bounded work-package contracts, and Terra's narrow first effect and conservative retirement discipline. Expand the resulting backlog to cover every current capability, with stock observation, strategy, accounting, controls and eventual execution named separately. Initial delivery can be small; final scope cannot be silently reduced to MCP.

No source plan should be adopted wholesale. All three need the new all-capability scope. Astra and Terra also carry factual assumptions corrected by Sol's stronger inspection of current source and retained telemetry. Sol's completion test is still too weak for the revised scope: a single promoted capability cannot demonstrate completion of the whole rewrite.

The later isolation instruction is adopted as a second material scope correction: keep legacy and rewrite independently executable in separate repositories/remotes, use a dedicated rewrite browser save, and never let both active owners control the same save's workers or shared resources. The original plans discussed namespace/generation separation but did not specify an independent repository and complete non-overwriting runtime strategy.

## Comparison rubric and planning-method limits

The rubric is evidence quality (25%), operational safety (20%), testability (15%), decomposition/handoff quality (20%), rollback clarity (10%), and whether a Terra-level agent can execute without guessing (10%). The table below provides qualitative evidence for those dimensions rather than invented precision scores. This rubric is recorded for this comparison; it was not supplied before the three original assignments, and their research windows/evidence packets were not controlled. Their relative findings therefore do not establish a general model-quality ranking.

The revised direction's method applies to the next assignments: version the supplied evidence packet, mark newly discovered evidence separately, publish this rubric before assigning work, use comparable bounded research windows and a common summary/package/evidence shape, and retain claim and decision-change tables. This is an evidence record, not the retired approval/governance ledger. An adversarial pass on the consolidated plan and a small disposable-browser feasibility proof remain required next steps; this synthesis does not claim either has already occurred.

## Facts independently checked during comparison

Repository HEAD read during consolidation was `e7af653db93e366f72d0fcd98510d897bb001fa3`. This identifies committed source, not all working-tree contents or executing game code. Existing edited/untracked planning files were preserved. No game call, deployment, source edit or test run was performed for this comparison; Sol's recorded 235-test/self-test result is attributed to Sol and must be re-run on the eventual implementation baseline.

1. **Home is currently excluded.** `mcp.js::getWorkerHosts` explicitly skips `home`. `HOME_RAM_RESERVE` and `getHostFreeRam` remain for compatibility/headroom calculations; their existence does not establish worker participation. Sol's conclusion is adopted. Astra's R7 table and Terra's suggestion that current code allocates home are rejected as current-state claims. Historical home-use observations remain history.

2. **Retained R8 firing evidence exists.** `mcp_events.txt`, run `mtrh1gm6-ig7p`, version `62f735`, sequences 1161–1170 contains available finite-score vetoes; sequence 1171 permits the switch at ratio approximately 0.8051, sequence 1172 drops `phantasy` for `b-and-a` on a potential-score comparison, and sequence 1173 adopts `phantasy` again. Sequences 1175–1177 repeat an allow/drop/re-adopt pattern. This directly supports Sol's correction of “never fired” and the replay requirement. It does **not** establish measured marginal benefit, fresh runtime conformance, a complete release identity, or environment identity absent separate provenance.

3. **The retained status has a money override.** `mcp_status.json` timestamp 1788819667406, same run/version, contains `OBJECTIVE:"money"`, `objectiveOverrideActive:true`, and `formulaRankingActive:true`. It is evidence of that snapshot, not a present-tense observation of Steam. An old XP entry in STATE cannot close R6's current-generation XP evidence gap.

4. **R8 can apply money effective scores to XP-qualified switches.** The objective-specific candidate comparison in `mcp.js` is followed by the R8 call without an objective gate. `getFormulaMinimumSecurityScore` returns formula `effective` money score, including ramp effects. Adopt Astra's finding as an explicit policy-review question, separate from the no-op handoff question. Do not fix it incidentally while moving code.

5. **Browser transport remains unresolved.** Terra relies on historical browser refusal; the local Python header comment claims a successful fix, and the sync manifest says the browser cannot use Remote API. Astra's inspected upstream `Remote.ts` implements conditional reconnect, contrary to the daemon's unconditional historical “never reconnects” statement. These contradictions require a pinned installed-version experiment, not selecting the prose one prefers. Upstream dev/cached source is not installed-game evidence.

6. **Stock has substantive existing behavior to migrate.** Direct reads of `mcp_stock_trader.js`, its logic/tests and stock docs show long-only forecast-based entries, a 10% profit target, a forecast-loss exit, adaptive 1%–10% portfolio cap, WSE/TIX/4S checks, retained position costs and dry-run mode. The rewrite must preserve or deliberately revise these semantics with evidence. No current short/order automation is inferred from API availability.

7. **Stock accounting needs its own acceptance work.** The buy path records a new purchase-cost quote after execution, and dry-run proposals do not deduct successive simulated buys from the shared budget. These are code-supported concerns to reproduce in stock fixtures, not a proven live misaccounting diagnosis. Test actual execution-price/fees and portfolio-wide simulated capital reservation; malformed accounting cannot silently become an empty trusted portfolio. Stopping a trader does not authorize selling its holdings.

8. **Cross-subsystem ownership is material.** `cct_worker_pool.js` preempts MCP action workers; `maintenance_steward.js` launches assessment work and recovery; `player_activity_controller.js` changes the player's single activity; rooting launches backdoor work; startup kills all home peers. A subsystem list without shared RAM, player-action, terminal-connection, cash and lifecycle arbitration is not an executable all-capability plan.

## Decisions adopted, corrected or rejected

- Adopt one observation/policy/gate/reconciler/executor pipeline as a shared contract, while retaining narrow specialized subsystem logic. Reject a new monolithic omnipotent manager and competing legacy/new owners.
- Adopt Sol's phased integration; replace its undifferentiated late expansion with explicit subsystem packages. Rooting, contracts, Darknet, stock, cloud workers, IPvGO, player activity, augmentation readiness, share, multi-target experiments and operational tools all receive coverage.
- Adopt Terra's harmless first owned-process effect and incremental retirement. Reject “MCP works, therefore rewrite complete.” Existing experimental features may remain experimental, but must be represented and supported through the new foundation.
- Adopt Astra's durable action-state semantics, environment fencing, spool saturation policy and finite experiments. Correct its outdated R7/R8 claims using the evidence above.
- Adopt numeric R1–R8 assessment order for a coherent review, followed by dependency-ordered experiments. A score-gate change, switch factor change, objective change and allocator change are not independent merely because their functions are separate.
- Use one prior `documentation-test-plan.md`, a small set of contracts and capability specs, a test catalogue, and evidence reports. Reject three competing normative document sets and parallel agents editing shared contracts simultaneously.
- The revised user scope supersedes exclusion of stock execution from the eventual plan. Initial stock work remains observation/proposal/accounting and an inert executor contract. Actual capital API implementation/delivery/activation must follow the project's specific approval boundary; the plan itself grants none. Do not reinterpret historical approval as permission for a newly broadened strategy, liquidation, shorts or resets.
- Audits end with fixed, accepted bounded limitation, rejected with evidence, or deferred capability. If an actual external reviewer or human action is needed, name the exact question and blocker while continuing unrelated packages; no invented review institution may block all progress.
- Adopt separate repositories/remotes and a dedicated rewrite save. Reject treating source branches, filenames or generation tags as sufficient isolation of game resources. Reject broad legacy-state overwrite during data migration and a shared watcher root during development.

The consolidated plan carries all four decisions; original source plans are preserved unchanged by instruction.
